# Design Deep Dive — Ink + Signal recommit (June 2026)

LifeOS recommits to **Ink + Signal**: true-black ink as the resting state, full-saturation domain hues only where they carry meaning, type-led hierarchy, and loud, flag-gated celebration that always ends.
The governing manifesto is **Answer First, Celebrate Loud, Rest Quiet** — five principles, each with a CI-locked "We never" sentence; prose with teeth, not prose alone.
Every screen must answer "what should I do next?" inside the first viewport; the Today hex radar is frozen in place by founder decision and every cluster designs with it, not around it.
[01-today-hero.md](01-today-hero.md) recomposes Today: fixed greeting header, deterministic `NextMoveHero` moved off Goals, radar hub + full-signal vertices, and the install banner evicted to an earned-moment sheet.
[02-cold-start.md](02-cold-start.md) replaces every day-1 zero with the action that creates its first value, collapses Rewards to one First Win, and promotes the first-ever block completion to an epic celebration.
[03-color-system.md](03-color-system.md) is the hard color recommit: `#000000` base, six full-saturation domain hues, violet restricted to five brand/AI surfaces, every ambient wash deleted, sign-in unified with the app.
[04-module-screens.md](04-module-screens.md) de-sludges the five module tabs: one hero per screen, value before form on Career, import prompts collapsed to bottom `ConnectRow`s, LABEL-CAPS killed.
[05-manifesto-guardrails.md](05-manifesto-guardrails.md) makes the philosophy enforceable: `DESIGN_MANIFESTO.md`, four jest grep-ratchets + one lock test, a binary review checklist, and the consumption contract below.
Sequencing is load-bearing: guardrails land first so they police the rest; color tokens land before any screen recomposition; Today, cold-start, and module waves follow behind flags.
73 binary acceptance criteria across the five specs are aggregated below verbatim; twelve cross-spec conflicts are resolved in this index, the stricter rule winning each time.

## How to consume this dossier

## Consumption contract — binding on the implementation-planning session
1. Acceptance criteria from this dossier are copied VERBATIM into implementation
   tasks — never paraphrased, never summarized, never merged. One criterion
   dropped = the task is incomplete by definition.
2. A wave is "done" only when every copied criterion is individually marked
   pass with evidence (screenshot, test name, or grep output) in the PR.
3. Token names, copy strings, regexes, and file paths in this dossier are exact.
   If a value must change during implementation, the change is recorded inline
   in the dossier with a dated note — silent drift is a defect.
4. The five compliance/lock tests in src/theme/__tests__/ land in the FIRST
   wave, before any visual work, so every later wave is born ratcheted.
5. Allowlist entries only shrink. Any plan step that adds one is invalid
   unless the PR carries the manifesto-change label with founder approval.
6. No plan step is allowed to soften manifesto wording ("never" → "avoid",
   "is" → "should be"). manifestoLock.test.ts makes this a red build.
7. Every plan task that touches a screen cites the manifesto principle(s) it
   serves, and ships the DESIGN_REVIEW_CHECKLIST filled in its PR.
8. If a task cannot meet a criterion, the task is escalated to the founder —
   it is never quietly rescoped to a weaker criterion.

## Cross-spec resolutions

Where two specs contradict, the stricter or more specific rule wins. Each resolution below amends the named spec(s); per consumption-contract line 3, the amendment must be recorded inline in the affected spec with a dated note before its wave starts. (Spec numbers: 01 = today-hero, 02 = cold-start, 03 = color-system, 04 = module-screens, 05 = manifesto-guardrails.)

1. **`*Light` → `*Dim` rename (03) supersedes every `*Light` reference elsewhere** — 01's `NextMoveHero` backgrounds read `c[\`${module}Dim\`]`, 02's firstWin preset paletteKey `primaryLight` becomes `primaryDim`, and 05's manifesto P3 "Compliant looks like" body + Guard B failure message say `*Dim` (the five locked sentences are unaffected).
2. **String-concat alpha tints in 01 (voice button `c.primary + '22'` / `c.primary + '55'`) violate 03 AC14 and 05 Guard B** — stricter wins: the voice button renders a `primaryDim` fill with a `border` hairline; no `+ 'XX'` construction ships anywhere.
3. **04 specifies `DOMAIN_GRADIENTS.social` / `DOMAIN_GRADIENTS.career` progress fills, but 03 deletes `DOMAIN_GRADIENTS` and the `gradientColors` prop** — stricter wins: all progress fills are solid domain hue on `c.track`.
4. **04 AC15 pins light-mode hero numerals to `lightColors.textPrimary` (`#140828`), but 03 replaces the light palette and adds per-mode `*Text` tokens** — more specific wins: hero numerals render in `c.{domain}Text` in both modes; AC15's hex literal is superseded by 03 §A.5.
5. **Explore week stat at zero: 02 keeps the `THIS WEEK` label with a StarterLine, 04 deletes the card, bans the string `THIS WEEK`, and renders nothing at zero** — stricter wins: 04's rule governs; the day-1 invitation lives in Explore's EmptyState hero, and 02 AC-7's Explore assertion is amended with a dated note.
6. **Health streaks zero state: 02 keeps the `STREAKS` SectionLabel with a starter line, 04 bans `STREAKS` and renders streak rows only at `n > 0`** — stricter wins: 04's rule governs the Health tab; 02's three-state rule survives only in the flag-off legacy tree.
7. **Today header XP at zero: 02 keeps the XpBar + `L1 → L2` with the caption `Your first block fills this bar.`, 01 deletes the XP bar from Today's header outright (01 Acceptance #12)** — stricter wins: with `today_answer_first_v1` on, 01's deletion governs; 02's caption applies only while that flag is off.
8. **New micro/caps hero metadata in 01 (eyebrows, hub sublines, uppercased date line) and 02 (`FIRST WIN` SectionLabel in the new `FirstWinCard.tsx`) trips 05 Guard D in non-allowlisted new files** — both rules hold: the strings qualify as data-metadata-inside-a-hero per 04 §3.0.2, but each new file still enters Guard D's allowlist via an explicit founder-approved `manifesto-change` entry; the ratchet is never bypassed silently.
9. **Domain-hue left rails: 03 kills borders-as-decoration app-wide, while 05's manifesto P3 sanctions "a 4px domain bar" and the 01/04 heroes use one** — reconciled to the stricter scope: a 4px domain rail is legal only on a screen's single hero, where the hue also carries ink or the CTA; every other card and list uses the R3 glyph mark.
10. **02 specifies `GlassCard accent={c.xp}` for FirstWinCard, but 03 removes GlassCard's `accent` prop** — stricter wins: FirstWinCard renders a neutral GlassCard with the `FIRST WIN` label inked in `c.xp` (R2 disposition).
11. **03 mandates ModuleHeader `stat={{ value: '—', label: 'BMI' }}` until vitals exist, but 04 §3.0.5 bans `—` placeholder vitals** — stricter wins: the Health header stat slot is omitted until a real BMI exists.
12. **Persist-key bump collision: 02 takes `lifeos_flags_v3` → `lifeos_flags_v4` at landing (default-true flag) and 01 also names v3 → v4 at fallback-flip** — resolved sequentially: 01's flip takes the next unused version at flip time (v5 if v4 is already taken), per the flag store's own bump convention.
